# GARAGE — информационная система автосервиса

GARAGE — учебный веб-проект для организации работы автосервиса. Система объединяет онлайн-запись клиентов, расписание специалистов, диагностику автомобилей и оформление заказ-нарядов. Данные хранятся в PostgreSQL.

## Возможности

### Для клиента
- Регистрация и вход в личный кабинет.
- Добавление и редактирование автомобилей.
- Просмотр каталога услуг, их стоимости и продолжительности.
- Запись на обслуживание: выбор автомобиля, услуг, специалиста и свободного времени.
- Просмотр своих записей и их статусов; отмена и перенос записи.
- Просмотр результатов диагностики, заказ-нарядов и истории обслуживания.
- Просмотр и редактирование личных данных, смена пароля и удаление аккаунта.
- Просмотр и скачивание прикреплённых к диагностике и заказ-нарядам файлов.

### Для мастера-диагноста
- Просмотр назначенных записей и заказ-нарядов.
- Работа с диагностикой: фиксация выявленных неисправностей и рекомендуемых работ.
- Ведение заказ-нарядов, изменение их статусов и добавление запасных частей с количеством и стоимостью.
- Прикрепление файлов к диагностике и заказ-нарядам.
- Просмотр рабочего расписания.

### Для администратора
- Управление каталогом услуг.
- Создание учётных записей мастеров и управление пользователями: изменение ролей, блокировка и восстановление доступа.
- Создание групп пользователей и управление их составом.
- Формирование рабочих интервалов специалистов и управление расписанием.
- Просмотр и управление записями, диагностикой и заказ-нарядами.

## Запуск проекта через Docker Compose

### Требования

- Docker Engine или Docker Desktop.
- Docker Compose.

### 1. Получение проекта

Клонируйте репозиторий или распакуйте архив проекта и перейдите в корневую папку, где находится `compose.yaml`:

```bash
cd Garage-dev-2
```

### 2. Настройка переменных окружения (`.env`)

Файл `.env` он содержит локальные настройки и пароль базы данных. **Перед первым запуском его необходимо создать самостоятельно** в корневой папке проекта — рядом с `compose.yaml`.

Создайте файл с именем `.env` (именно с точкой в начале) и добавьте в него:

```env
POSTGRES_PASSWORD=your_strong_password
```

Замените `your_strong_password` на собственный надёжный пароль. Например, можно сгенерировать длинную случайную комбинацию букв и цифр. Не используйте приведённое значение как реальный пароль.

Переменная `POSTGRES_PASSWORD` обязательна: файл `compose.yaml` передаёт её контейнеру PostgreSQL как пароль пользователя базы данных `garage`, а также серверной части для подключения к этой базе. Если переменная не задана, Docker Compose остановится с сообщением `set POSTGRES_PASSWORD in .env`.

Для запуска через Docker Compose дополнительных переменных в `.env` не требуется: имя базы (`garage`), пользователь (`garage`) и адрес базы внутри сети контейнеров (`db`) уже заданы в `compose.yaml`.

Проверьте, что файл находится именно здесь:

```text
Garage-dev-2/
├── .env              # создать самостоятельно
├── compose.yaml
├── Dockerfile
└── ...
```

Файл `.env` содержит секретные данные. Не публикуйте его и не добавляйте в Git-репозиторий. Для каждого окружения следует использовать собственный пароль.

> **Важно:** если контейнер PostgreSQL уже запускался и создал том `garage-postgres`, простая смена `POSTGRES_PASSWORD` в `.env` не изменит пароль пользователя в уже инициализированной базе. Для чистой учебной установки можно удалить том командой `docker compose down -v`, а затем запустить проект заново. Это удалит все данные базы данных.

### 3. Сборка и запуск

```bash
docker compose up --build -d
```

При запуске Compose:
1. Создаёт контейнер PostgreSQL и постоянный том для данных.
2. Дожидается готовности базы данных.
3. Собирает и запускает серверную часть.
4. Выполняет миграции Alembic (`alembic upgrade head`) при старте backend.
5. Собирает React-приложение и запускает Nginx.

### 4. Открытие приложения

После успешного запуска откройте в браузере:

```text
http://localhost:8080
```

Frontend доступен через Nginx. Запросы с префиксом `/api/` проксируются на FastAPI.

### 5. Создание администратора

Регистрация через интерфейс создаёт пользователя с ролью клиента. Для создания администратора предусмотрен отдельный интерактивный скрипт:

```bash
docker compose exec backend python -m backend.create_admin
```

Скрипт запросит имя, адрес электронной почты и пароль. Пароль должен содержать не менее 8 символов; при вводе он не отображается. После создания войдите в приложение с указанными данными.

## Полезные команды Docker Compose

Посмотреть состояние контейнеров:

```bash
docker compose ps
```

Посмотреть журналы всех сервисов:

```bash
docker compose logs -f
```

Посмотреть журнал серверной части:

```bash
docker compose logs -f backend
```

Остановить контейнеры, сохранив данные базы:

```bash
docker compose down
```

Остановить контейнеры и удалить том PostgreSQL (все данные базы будут удалены):

```bash
docker compose down -v
```

Повторно собрать и запустить приложение:

```bash
docker compose up --build -d
```

## База данных

Для хранения данных используется PostgreSQL 16. SQLAlchemy-модели расположены в `backend/core/models.py`, исходная SQL-схема — в `schema.postgresql.sql`, миграции — в каталоге `alembic/versions/`.

Основные таблицы:

- `roles`, `users`, `sessions` — роли, пользователи и пользовательские сессии;
- `user_groups`, `user_group_members` — группы пользователей и их состав;
- `vehicles` — автомобили клиентов;
- `services` — каталог услуг автосервиса;
- `schedule_slots` — рабочие интервалы специалистов;
- `appointments`, `appointment_services`, `appointment_slots` — записи на обслуживание и выбранные услуги;
- `diagnostics` — результаты диагностики;
- `work_orders`, `work_order_parts` — заказ-наряды и запасные части;
- `attachments` — файлы, прикреплённые к диагностике или заказ-нарядам.

Данные PostgreSQL сохраняются в Docker-томе `garage-postgres` и не удаляются при обычной команде `docker compose down`.

## API

Серверная часть реализована на FastAPI. Основные группы маршрутов:

| Префикс | Назначение |
|---|---|
| `/auth` | Регистрация, вход, выход и проверка текущей сессии |
| `/profile` | Данные и настройки учётной записи |
| `/users`, `/groups` | Пользователи и группы |
| `/masters` | Специалисты автосервиса |
| `/vehicles` | Автомобили |
| `/services` | Каталог услуг |
| `/slots` | Рабочие интервалы и расписание |
| `/appointments` | Записи на обслуживание |
| `/diagnostics` | Диагностика |
| `/work-orders` | Заказ-наряды и запасные части |
| `/files` | Работа с прикреплёнными файлами |

Интерактивная документация FastAPI доступна по адресу `/docs` на сервере API. При запуске через Compose backend напрямую не публикует порт на хост, поэтому документацию можно открыть внутри сети контейнеров или временно опубликовать порт backend в `compose.yaml` для локальной разработки.

## Локальная разработка без Docker

Для запуска отдельных частей проекта локально потребуются Python 3.12, Node.js 24+, npm и доступный сервер PostgreSQL.

1. Установите зависимости Python:

   ```bash
   pip install -r requirements.txt
   ```

2. Настройте переменные подключения к PostgreSQL. Приложение поддерживает `DATABASE_URL` либо набор переменных `POSTGRES_HOST`, `POSTGRES_PORT`, `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD`.

3. Примените миграции и запустите API:

   ```bash
   alembic upgrade head
   uvicorn backend.main:app --reload
   ```

4. В отдельном терминале установите зависимости frontend и запустите Vite:

   ```bash
   cd frontend
   npm ci
   npm run dev
   ```

   По умолчанию Vite проксирует `/api` на `http://127.0.0.1:8000`. При необходимости адрес можно изменить через переменную `API_PROXY_TARGET`.
